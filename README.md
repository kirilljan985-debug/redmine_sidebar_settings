# Redmine Sidebar Settings

Настройка сайдбара Redmine **только на уровне отображения**: администратор
может переименовывать, скрывать и переставлять секции и ссылки сайдбара —
включая пункты, добавленные другими плагинами. Функции, ссылки и права
доступа не затрагиваются: скрытый пункт остаётся в DOM и доступен по прямому
URL.

Совместимость: Redmine **7.0+** (проверяется CI на `7.0-stable` и `master`).

## Возможности

- Переименование секций (`h3`) и ссылок сайдбара (иконки ссылок сохраняются).
- Скрытие секций и ссылок — только `display: none`, ничего не удаляется.
- Перемещение секций (включая блоки чужих плагинов) по вертикали.
- Правила привязываются к страницам: `*` (все), `controller/*` (модуль),
  `controller/action` (конкретная страница).
- Цели правил: по заголовку секции, по пути ссылки (префикс) или CSS-селектором
  (аварийный люк для нестандартных элементов чужих плагинов).
- Раздел «Сайдбар» в Администрировании с редактором правил; «сырой» JSON
  остаётся доступен как запасной путь.
- Отказоустойчивость по построению: битый конфиг, отсутствие JS или ошибка
  движка — страница остаётся полностью нативной.

## Установка

```bash
cd /path/to/redmine/plugins
git clone https://github.com/kirilljan985-debug/redmine_sidebar_settings.git
```

и перезапустить Redmine. Миграций и дополнительных гемов нет.

Redmine 7 (Propshaft): при первом развёртывании в production может
потребоваться `bundle exec rake assets:precompile`.

## Использование

Администрирование → **Сайдбар**. Каждая строка — правило:

| Поле | Значение |
|------|----------|
| Страница | `*`, `controller/*` или `controller/action` |
| Действие | Переименовать / Скрыть / Переместить |
| Цель | Заголовок секции (точный текст) · Ссылка (путь или префикс) · CSS-селектор |
| Новое название | для «Переименовать» |
| Позиция | для «Переместить» (0 — первая; считается по текущему порядку секций) |

Правила применяются сверху вниз: сначала глобальные (`*`), затем модульные
(`controller/*`), затем точные (`controller/action`); внутри группы — в порядке
хранения.

Пример:

```json
[
  {"page": "*", "action": "hide", "target": {"heading": "Справка"}},
  {"page": "issues/index", "action": "rename", "target": {"heading": "Запросы"}, "value": "Представления"},
  {"page": "issues/index", "action": "move", "target": {"kind": "section", "heading": "Мои запросы"}, "index": 0},
  {"page": "*", "action": "rename", "target": {"kind": "item", "href": "/issues?query_id="}, "value": "Сохранённый фильтр"},
  {"page": "wiki/show", "action": "hide", "target": {"css": ".my-plugin-block"}}
]
```

Матчинг ссылок — по нормализованному пути (путь + query) с проверкой префикса:
цель `/issues?query_id=` покрывает все сохранённые запросы разом.

## Ограничения

- Матчинг секций — по тексту заголовка: он зависит от языка интерфейса и может
  измениться при обновлении Redmine (страховка — CSS-селектор).
- Пункт вики-страницы «Sidebar» — произвольный контент вики, плагин его не
  трогает (это не кнопки ядра).
- Движок работает и на контенте, добавленном другими плагинами асинхронно
  (MutationObserver), но экзотические плагины, рисующие сайдбар полностью
  своим JS с большой задержкой, правьте CSS-правилами.
- Скрытие — отображение, а не права доступа: ссылка остаётся доступной по URL.

## Разработка и тесты

```bash
bundle exec rake redmine:plugins:test NAME=redmine_sidebar_settings RAILS_ENV=test
```

CI (GitHub Actions) гоняет матрицу Redmine `7.0-stable` / `master` на sqlite и
обязательный eager-load smoke check (имитация production).

Локальный стенд движка без Redmine: `dev/preview.html`
(`python -m http.server 8123` из корня плагина → `http://127.0.0.1:8123/dev/preview.html`).
